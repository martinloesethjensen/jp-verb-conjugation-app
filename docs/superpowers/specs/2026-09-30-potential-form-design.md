# Potential Form Deep-Dive — Design

**Date:** 2026-09-30
**Status:** Approved in brainstorming, pending written-spec review
**Builds on:** [2026-09-29-grammar-foundation-nd-desu-design.md](2026-09-29-grammar-foundation-nd-desu-design.md)
(sub-project 1) and the [native rewrite spec](2026-09-23-native-apple-rewrite-design.md).
This is **sub-project 2** of the grammar work.

## Summary

Add the potential form (可能形) in two parts:

- A **lesson**, `potential`, in the Grammar tab: how the form is built for each
  verb class, what it expresses, the が/を/には particle choices, できる and
  ことができる, 見える/聞こえる versus 見られる/聞ける, its own conjugations, and
  four common pitfalls.
- **Per-verb potential forms**: the nine forms a verb's potential conjugates
  into, stored in `verbs.json`, generated by the data script, and shown in a
  new "Potential" section on the verb detail page, linked to the lesson.

The rewrite spec stored only the base potential form per verb and explicitly
left its own conjugations out of scope ("flag if you actually want that
depth"). This sub-project is that flag.

It reuses sub-project 1's infrastructure wholesale: the `GrammarPoint` model,
`grammar.json` and its sync, the Grammar tab, `Route` / `openRoute`, and the
`scripts/update_data.py` pipeline. **No change to the grammar model is
needed**: a lesson's attachment rows already carry an optional `condition`,
which is how the four verb-class rows are expressed.

## 1. Per-verb data

`potential` already exists on `VerbForms` (optional, currently empty for all 25
verbs) and stays the base form: plain, present, affirmative. **Eight new
optional fields** complete the verb's own grid, so each verb has nine
potential forms in total, matching how the verb page lays out polite / plain /
て-form:

| JSON key | Example (たべる) |
|---|---|
| `potential` *(existing)* | たべられる |
| `pot_masu_pos` | たべられます |
| `pot_masu_neg` | たべられません |
| `pot_masu_past` | たべられました |
| `pot_masu_past_neg` | たべられませんでした |
| `pot_te` | たべられて |
| `pot_short_neg` | たべられない |
| `pot_short_past` | たべられた |
| `pot_short_past_neg` | たべられなかった |

Plus `VerbForms.hasPotentialForms: Bool` (true when any of the nine is set).
Same conventions as the `nd_*` fields: optional, snake_case, stored in
`verbs.json`, and **no `FormKey` cases**, so the potential forms do not appear
in quiz questions. The forms are kana, like all the verb data.

### Generation

`scripts/update_data.py` gains a deterministic step, run alongside the `nd_*`
step, with the same idempotence and stale-field repair:

1. **Base form** from the verb's class:
   - **Ru-verbs** (`type: ru`): drop る, add られる (たべる → たべられる,
     みる → みられる).
   - **U-verbs** (`type: u`): the last kana moves to its え-row, then る. The
     nine endings present in the data: う→え, く→け, ぐ→げ, す→せ, つ→て,
     ぬ→ね, ぶ→べ, む→め, る→れ (のむ → のめる, かう → かえる, とる → とれる).
   - **Irregulars** (`type: irr.`): する → できる, くる → こられる.
2. **The other eight forms.** A potential verb is itself an ichidan verb, so
   the eight remaining forms come from the standard ichidan rules applied to
   the base (drop る, then ます / ません / ました / ませんでした / て / ない /
   た / なかった).
3. **Exceptions.** A small `NO_POTENTIAL` set holds verbs with no regular
   potential. It contains **ある**; such verbs get no potential fields, and any
   stale ones are removed. The set is easy to extend (for example with わかる)
   and is the only hand-maintained part.

The script does not touch `notes` or `description`. The manifest's verbs
version is bumped by the script (to 1.2.0) since `verbs.json` changes.

### ある's note

ある keeps its existing note (*"Pair with いる (for living things): 本がある vs
犬がいる."*) and gains one sentence: that it has no potential form, and that
ありえる ("can happen") is a separate word. This is the one hand-edited change
to `verbs.json`; the script re-hashes it.

## 2. Verb page

A dedicated **Potential** section, following the んです section's pattern.
(The alternative, putting the forms inside the collapsed, usually-hidden
Advanced section, would bury the feature and mix a nine-form grid with
single-form tiles.)

- **`PotentialFormsSection`** (new view). Nine glass tiles in the same
  two-column style as the existing form groups: plain ± present and past,
  polite ± present and past, then て-form. Collapsed by default. Hidden when the
  verb has no potential forms, so ある shows nothing.
- **Link.** "Learn about the potential form", through `openRoute`, hidden until
  the lesson has synced. It works from a Grammar tab that has never been opened
  (the `preferredCompactColumn` mechanism from sub-project 1).
- **Section order:** Polite, Plain, て-form, **Potential**, Advanced (only if
  other advanced forms exist), んです. Potential comes straight after the
  forms it derives from, before the pattern sections.
- **Advanced stops special-casing potential.** `VerbDetailView` currently lists
  `potential` among Advanced's tiles and counts it when deciding whether to
  show that section. Both references are removed, so filling `potential` does
  not make a lone-tile Advanced section appear. The other eight advanced
  fields are untouched.
- Visual style follows the rewrite spec's section 10: `.glassEffect()`
  surfaces, glass buttons, and no accessibility-specific modifiers.

## 3. The lesson

`id: potential` (also exposed as `GrammarPoint.potentialID`, like `nDesuID`),
title **可能形**, level beginner. Summary: *"The potential form says that someone
can do something, or that the situation allows it: 食べられる, 飲める, できる.
It conjugates as a ru-verb."* The summary names the form in English on purpose:
list search matches the title, summary and Japanese example text, and the title
is only 可能形, so without "potential" in the summary an English search would
find nothing. Lesson text is written independently, not copied
from Yokubi; examples use mostly hiragana with kanji where natural.

### How it forms (`attachment`, all `wordClass: verb`, one row per condition)

| Condition | Rule | Examples |
|---|---|---|
| Ru-verbs | drop る + **られる** | 食べる → 食べられる · 見る → 見られる |
| U-verbs | change the last kana to its **え-sound** + る | 飲む→飲める · 書く→書ける · 話す→話せる · 買う→買える · 泳ぐ→泳げる · 待つ→待てる · 死ぬ→死ねる · 遊ぶ→遊べる · 取る→取れる |
| する | → **できる**, a different verb | 勉強する → 勉強できる |
| 来る | → **来られる** (こられる) | 来る → 来られる |

The ru-verb row notes that the form is identical to the passive. The u-verb row
notes the vowel shifts.

### Usages (`usages`)

1. **Ability.** The person has the skill. — 私は漢字が読めます。· 兄は三キロ泳げます。
2. **Possibility and circumstances.** The situation allows it, which is
   different from skill. The negative is the polite way to decline, and leads
   into the んです lesson. — 今日は行けません。· この店ではカードが使えます。·
   明日なら会えます。
3. **が, を and には.** The thing that can be done normally takes が; を is
   common in speech; the person who can takes には. — すしが食べられますか。/
   すしを食べられますか。· 私にはこの漢字が読めません。
4. **できる and ことができる.** できる with nouns, and the formal ことができる
   that works with any verb. — 日本語ができますか。· 泳ぐことができます。·
   あしたは勉強できません。
5. **見える / 聞こえる vs 見られる / 聞ける.** Spontaneous perception versus
   having the chance or ability. — 富士山が見えます。· 鳥の声が聞こえます。·
   この曲は無料で聞けます。

### Its own conjugations (`conjugations`)

- **Polite:** られます / られません / られました / られませんでした (each row's note gives the u-verb equivalent, for example 飲めます).
- **Casual:** られる / られない / られた / られなかった, and the て-form
  られて, which is for linking clauses and giving reasons, not for requests.
- **Formal:** ことができる / ことができません.

### Watch out (`pitfalls`)

- **Potential vs passive.** For ru-verbs and 来る they are identical. *私は
  納豆が食べられます。* (can eat) versus *ケーキを妹に食べられた。* (my cake got
  eaten: the "adversity" passive). U-verbs differ (飲める versus 飲まれる).
- **ら抜き言葉.** 起きれない for 起きられない is very common in speech and is
  treated as casual or non-standard in writing. It applies only to ru-verbs and
  来る, never to u-verbs. Taught here as a pitfall with a register note; it is
  not stored as data on each verb. Examples show both forms.
- **"Can" is not "may".** 写真が撮れます says it is possible; permission is
  撮ってもいいです.
- **No potential.** ある has none; ありえる is a separate word meaning "can
  happen" (*そんなことはありえない。*). わかる already means "can be
  understood". The app shows no potential section for ある.

### Related

`related: ["n-desu"]`, and the んです lesson gains `related: ["potential"]`,
which adds a "Related" row to that lesson with no UI change.

### Judgment calls recorded

- The ピアノが弾ける / ピアノができる contrast is **not** included:
  ピアノができる is not natural Japanese.
- れる-for-られる forms are described as "casual, very common in speech", not
  as wrong. If the lesson should call them plainly incorrect, that is a text
  change only.
- いる is not claimed to lack a potential, because 居られない exists.

## 4. Testing

- **Script (Python).** Hand-verified potential forms for ru, for each of the
  nine u-ending kinds, for する and くる; ある producing none; all nine
  conjugations for one verb per class; idempotence; stale-field removal for
  exceptions. The existing lesson validator already checks the schema and that
  every `related` id exists.
- **Model (Swift).** The eight `pot_*` fields decode and encode with the right
  keys, old data without them still decodes, and `hasPotentialForms` behaves.
- **Real data (Swift).** All 25 verbs checked against the formation rules, with
  spot checks per class and ある having none. The lesson has the agreed shape
  (five usages, four attachment rows, four pitfalls), its `related` link
  resolves, and the manifest hashes match.
- **Existing behavior.** Search and `Route` tests already cover the new lesson's
  text. Verb-page behavior is verified in the Simulator, not with UI tests: a
  ru-verb (たべる), a u-verb (のむ), くる, ある showing no section, the link
  landing on the lesson from a never-visited Grammar tab, and Advanced staying
  hidden.

Because the forms are generated from each verb's `type` and `teGroup`, an
incorrect class in the data would produce incorrect potential forms; the
all-25-verbs real-data test is the safety net.
