# A first launch that works offline: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A first launch with no network opens the app with all data present, by installing bundled copies of the six data files into the persisted store as if they had been synced.

**Architecture:** `update_data.py` writes a byte-for-byte copy of each data file plus a `{version, sha256}` sidecar into the VerbKit resources. A generic `BundledData<Value>` loads and checks one. Each store, in `start()` before its cached load, installs its bundle when the bundled version is strictly newer than the device's rollback floor: persist, then `confirmSynced(manifest)` (which records both the last-synced manifest and the floor). Sync services need no change, and the in-memory counters bundle is reworked onto this rule.

**Tech Stack:** Python (unittest), Swift 6, VerbKit (XCTest), SwiftData, iPhone simulator.

**Spec:** `docs/superpowers/specs/2026-10-27-offline-first-launch-design.md` (decisions and the builder's answers are in it). All three decisions were approved by the owner on 2026-10-27.

## Base branch

Build this on top of `counters-big-numbers-stage-1` (or on `main` once that branch is merged), **not** on `main`
as it is today: Task 5 reworks the counters bundle (`BundledCounters`, `CountersStore`'s in-memory fallback) that
only exists there. No `data/` content changes in this plan, so the owner's signature on that branch stays
valid; the new bundled copies are generated from the same data.

## Global Constraints

- The bundled copies are generated by `make data`, never hand-edited; `make data-check` fails if any copy or sidecar differs from `data/` and the manifest.
- Install only when the bundled version is strictly newer than the floor (`highestAcceptedVersion`), or there is no floor. An unreadable bundled version never installs. Equal or older never installs.
- Persist first, record the manifest only after the save succeeds; a failed install keeps the old cache and records nothing.
- A bundle that is missing, unreadable or does not match its sidecar is treated as absent: a cache is used silently, and with no cache the first-launch gate behaves as today.
- Stores take their bundle as an optional parameter defaulting to none, so existing store tests keep exercising the no-bundle path.
- Old caches and old app builds keep working. No UI change except the "bundled" label in Settings > Data.
- Every `data/` change is re-signed by the owner; the bundled copies are not part of the signature.

## Review Focus

- A bundle older than the floor never replaces newer data (a restored or sideloaded older build). Task 3.
- A failed install keeps the old cache and records no manifest. Task 3.
- An equal version does not reinstall, so a normal launch does not re-persist 260 KB of verbs. Task 3.
- A corrupt bundle with a cache present uses the cache silently; with no cache the gate shows as today. Task 3.
- Verbs install but grammar fails: verbs still show, grammar waits for a sync. Task 3.
- The Counters widget sees the bundled counters (they are in the persisted store, not only in memory). Task 5.
- A bundled copy cannot drift from `data/`. Task 1.
