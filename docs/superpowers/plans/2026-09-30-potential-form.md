# Potential Form Deep-Dive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the potential form (可能形): a Grammar-tab lesson, nine generated potential forms per verb stored in `verbs.json`, and a "Potential" section on the verb page linked to the lesson.

**Architecture:** Sub-project 1's machinery carries almost all of it. The lesson is one more entry in `grammar.json` (no model change: the four verb-class rows use `AttachmentRule.condition`). `scripts/update_data.py` gains a deterministic potential-form step beside the `nd_*` one. `VerbForms` gains eight optional `pot_*` fields, and a new `PotentialFormsSection` mirrors the んです section.

**Tech Stack:** Swift 5 language mode on Xcode 27 (SwiftPM tools 6.2), SwiftUI with Liquid Glass, XCTest; Python 3 (standard library only); XcodeGen 2.46.

**Spec:** [docs/superpowers/specs/2026-09-30-potential-form-design.md](../specs/2026-09-30-potential-form-design.md), which builds on [the grammar foundation spec](../specs/2026-09-29-grammar-foundation-nd-desu-design.md) and the [native rewrite spec](../specs/2026-09-23-native-apple-rewrite-design.md) (read its section 10, the visual design direction).

**Verified against:** `main` at `2f59401` plus the spec commit `7469022`. Every task below was executed on a scratch branch (one commit per task) with all tests passing, both app targets building, and the app run in the iOS Simulator against local copies of the data. **If `main` has moved since, run Task 0 Step 2 first.**

## Global Constraints

- Deployment target: **iOS 26 / macOS 26**, Swift language mode 5. Do not lower it.
- **Patch existing files; never replace them wholesale.** `main` changes underneath this work (another session is changing the pill colours in `VerbRow.swift`, `VerbDetailView.swift`, `TeFormLegend.swift` and `VerbColors.swift`). Modified files are given as diffs against `7469022`: apply with `git apply --3way`, or make the equivalent edit by hand if the surrounding code has moved.
- `potential` already exists on `VerbForms`; it stays the base form (plain, present, affirmative). The eight new fields are **optional**, snake_case in JSON: `pot_masu_pos`, `pot_masu_neg`, `pot_masu_past`, `pot_masu_past_neg`, `pot_te`, `pot_short_neg`, `pot_short_past`, `pot_short_past_neg` (spec §1).
- The potential fields are generated by `scripts/update_data.py` from each verb's `type` and kana `dict` form, never by hand. The script owns all nine fields: it overwrites a hand-set value and removes them for verbs in `NO_POTENTIAL` (which contains **ある** only).
- `pot_*` get **no** `FormKey` cases, so they do not appear in quiz questions (spec §1).
- The Potential section sits directly after て-form, before Advanced and んです. It is collapsed by default, hidden when the verb has no potential forms, and its lesson link is hidden until the lesson has synced (spec §2).
- Advanced must no longer list or count `potential`: filling the field must not make a lone-tile Advanced section appear (spec §2).
- Visual design direction (rewrite spec §10): custom surfaces use `.glassEffect(...)` and `.glass` button styles; standard containers are left alone; **no accessibility-specific modifiers** (`.accessibilityLabel`, `.accessibilityHint`, …).
- Lesson text is written independently, not copied from Yokubi. Examples use mostly hiragana with kanji where natural. Do not include the ピアノができる contrast (not natural Japanese); describe ら抜き as casual and common in speech, not as wrong; do not claim いる has no potential (spec §3).
- `data/verbs.json` and `data/manifest.json` are changed only by running `scripts/update_data.py` (the one exception is the hand-edited note on ある, in Task 3). `data/grammar.json` is hand-authored. Hashes must match the files byte for byte.
- Out of scope: furigana (sub-project 5), the other forms (volitional, passive, …), potential in the quiz, ら抜き as per-verb data, exceptions beyond ある (spec, "Not in this sub-project").
- Any `git push` to the GitHub remote requires explicit user confirmation at execution time. Do not push without asking first.

import SwiftUI
import VerbKit

/// The verb's nine potential forms — plain, then polite, then て-form — plus a
/// link to the lesson. Shown on verb detail only when the verb has potential
/// forms, so ある (which has none) shows nothing.
struct PotentialFormsSection: View {
    let forms: VerbForms
    @Environment(VerbStore.self) private var verbStore
    @Environment(\.openRoute) private var openRoute
    @State private var isExpanded = false

    /// (label, value) for every form this verb has, in display order. The
    /// labels are the ones the other form sections already use.
    private var tiles: [(String, String)] {
        let all: [(FormKey, String?)] = [
            (.shortPos, forms.potential),
            (.shortNeg, forms.potShortNeg),
            (.shortPast, forms.potShortPast),
            (.shortPastNeg, forms.potShortPastNeg),
            (.masuPos, forms.potMasuPos),
            (.masuNeg, forms.potMasuNeg),
            (.masuPast, forms.potMasuPast),
            (.masuPastNeg, forms.potMasuPastNeg),
            (.te, forms.potTe),
        ]
        return all.compactMap { key, value in
            guard let value, let label = formLabels[key] else { return nil }
            return (label, value)
        }
    }

    /// The link is hidden until the lesson has synced, so it never dead-ends.
    private var lessonIsAvailable: Bool {
        Route.grammar(GrammarPoint.potentialID)
            .resolve(verbs: [], grammarPoints: verbStore.grammarPoints) != nil
    }

    var body: some View {
        DisclosureGroup("Potential", isExpanded: $isExpanded) {
            VStack(alignment: .leading, spacing: 12) {
                LazyVGrid(columns: [GridItem(.flexible()), GridItem(.flexible())], spacing: 8) {
                    ForEach(tiles, id: \.0) { label, value in
                        VStack(alignment: .leading, spacing: 2) {
                            Text(label)
                                .font(.caption2)
                                .foregroundStyle(.secondary)
                            Text(value)
                                .font(.headline)
                                .lineLimit(1)
                                .minimumScaleFactor(0.7)
                        }
                        .frame(maxWidth: .infinity, alignment: .leading)
                        .padding(8)
                        .glassEffect(in: RoundedRectangle(cornerRadius: 8))
                    }
                }

                if lessonIsAvailable {
                    Button {
                        openRoute(.grammar(GrammarPoint.potentialID))
                    } label: {
                        Label("Learn about the potential form", systemImage: "arrow.right.circle")
                    }
                    .buttonStyle(.glass)
                    .font(.subheadline)
                }
            }
            .padding(.top, 4)
        }
        .font(.subheadline.weight(.semibold))
    }
}
